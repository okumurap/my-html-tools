# HTMLアプリ共通の完成条件

`tools/` 以下の追加・修正に適用します。[ルートのAGENTS.md](../AGENTS.md) の構成・Git・公開・安全方針と、対象アプリ内の追加ルールを併用します。条件は該当する変更に適用し、省略・未確認の理由を報告します。

## 1. 着手前の調査

- 対象ファイル、現在の入力・出力・保存・コピー・エクスポート・Undo/Redo・画面切替など、維持すべき操作を把握します。代表的な操作を最低3件書き出します。軽微な文言変更等では影響範囲に応じて簡略化できます。
- **実装前の既存コード調査は必須です。** `tools/` と `assets/` の関連箇所から、UI部品・入力操作、localStorage保存／復元、グラフ描画、Undo/Redoの再利用候補を調べます。関連しない全ファイルを無差別に読む必要はありません。
- 候補の動作・依存・データ形式・ライセンス・既存アプリへの影響を確認して流用します。流用が不適切なら理由を簡潔に記録します。単体HTMLの独立性を壊す共通化や大規模な変更は勝手に行いません。
- [tests/README.md](../tests/README.md) と対象アプリ内のテストを確認し、関連する既存テストを変更前に可能な範囲で実行します。既存の失敗は変更で生じた失敗と区別します。

## 2. 実装の基本

- HTMLは `<!doctype html>`、`lang="ja"`、`meta viewport` を設定し、セマンティックな要素を使います。操作は原則button、入力は対応するlabelを設けます。
- CSSはモバイルファースト、主要色・余白はCSS変数で管理します。色だけの状態表現、不要な装飾・アニメーションを避け、可能ならOSのダークモードに対応します。
- タップ領域は原則44px程度を確保します。hover・右クリック・ドラッグだけを必須にせず、タップで使える代替操作を用意します。
- JavaScriptはconstを基本とし、DOM取得・イベント・計算処理を読みやすく整理します。不要なグローバル変数・デバッグ出力を残しません。テストの結果出力はこの制限の対象外です。
- 入力を検証し、失敗時は日本語で理由・現在の状態を表示します。保存キーはアプリ固有の接頭辞を付け、既存キーを変える場合は互換性を確認します。

## 3. 共通の検証

- **回帰**：変更した操作と、着手前に整理した主要操作を実行します。該当するコピー・保存・入出力・Undo/Redo・画面切替・戻る操作も確認します。
- **境界**：通常値、空欄、0、最小・最大、範囲外、負値、非数値、長い文字列を確認します。許容しない入力は黙って誤計算せずエラーにします。
- **構文・実行時**：HTMLのタグ、JS構文、ブラウザのコンソール、外部通信・依存の失敗時の挙動を確認します。確認できなければ未確認と記載します。
- **公開パス**：`/my-html-tools/` 相当のサブパスで、CSS・JS・画像・アプリ間リンクが解決されることを確認します。
- **差分**：意図しない変更・秘密情報・不要な依存追加がないことを確認します。

## 4. スマートフォン・画面の確認

- 幅320px・375px・768px・デスクトップ相当で、主要画面と操作を確認します。ページ全体の意図しない横スクロールを出さず、横長の表などは必要な部分だけスクロールさせます。
- **日本語が読めるフォントでスクリーンショットを撮り、実際に目視確認します。** 自動判定で横幅が収まっただけでは完了にしません。文字化け・代替文字の画面で文字配置を検証済みにしません。
- 縦方向の見切れ、重なり、固定ヘッダー／フッター、overflowによる隠れ、スクロールしても到達できない入力・ボタンを確認します。長いデータ・エラー表示・パネル展開後も確認します。
- 375pxでは主要操作をタップだけで完了できることを確認します。入力欄へのフォーカス、編集確定、メニュー選択も含めます。画面幅・タッチのエミュレーションを実機確認と呼びません。
- スクリーンショットや実機を利用できない場合は、代替検証の範囲と残る未確認事項を示します。

## 5. 計算・グラフ

- 代表値を**最低3ケース**、実装とは独立した手計算・式・検証用スクリプトと照合します。公式・単位・丸めの位置を明示し、本体と同じ計算処理の再実行だけを正解の根拠にしません。
- 0、上下限、単位・桁違い、分母0、未定義・発散を確認します。公差の最小・最大は最悪の組合せで評価し、上下限の逆転がないことを確認します。
- 入力変更後の数値・表・グラフ・凡例・軸名・単位・表示範囲が同じ条件を示すことを確認します。軸の向き・ラベル反転・丸めの食い違いも確認します。
- 推定・概算と確定値を区別し、重要な前提・適用範囲を表示します。未検証の式を検証済みと表現しません。

## 6. 保存・ファイル入出力と失敗後の状態

- 保存キーや形式を変える場合は旧形式の読込・移行を確認します。移行できない場合は理由と影響を報告し、既存データを無断消去しません。
- JSON/CSV等は書き出し→読み込みで値・型・順序が保持されるか確認します。破損・不正形式・範囲外は取り込み前に検証し、途中まで反映して既存状態を壊しません。
- **読込失敗後に、以前の結果を新しいファイルの結果として表示しません。** 結果を無効化するか、前回結果であることを明示し、ファイル名・条件・結果を一致させます。
- **破損した保存データを空データ扱いして自動上書きしません。** 復旧または明示的な削除まで既存内容を保持します。
- **保存容量不足・保存禁止でも編集中の内容を失わず、保存失敗を表示します。** 保存成功したように見せません。
- **非同期読込は最後の操作を優先します。** 先に開始した処理の遅い完了が、後から選んだファイルや入力の結果を上書きしないことを確認します。失敗応答も同様です。
- 再読み込み後の復元、リセット・削除の対象、同名保存・取り込みの挙動、自動保存の有効／無効、Undo後の状態を確認します。コピーした内容は見た目と一致させます。

## 7. ゲーム・端末機能

- ゲームは開始→操作→終了→再プレイと、入力がない場合の挙動を確認します。
- ジャイロ・音・全画面・クリップボード・ファイル選択等は、権限拒否・未対応・API失敗時に説明または代替操作を用意します。スマートフォンでもドラッグ以外でファイルを選べるようにします。
- 実機未確認、APIのモックのみでの確認、実クリップボードでの確認を区別して記録します。

## 8. テストの残し方と完了判定

- 不具合修正では、可能な限り**修正前に失敗し、修正後に通る再現テスト**を残します。ユーザーの操作・期待結果を検証し、実装を写しただけのテストにしません。旧コードで再現確認できなければその制約を記録します。
- 自動化できない不具合は、入力・操作・期待結果を再現手順として残します。軽微な文言・色だけの変更に、形式的なテストコード追加は要求しません。
- 関連する既存テストと影響範囲の回帰を優先します。共通アセットを変えた場合はその利用先も確認し、無関係な全アプリの再検証は求めません。
- 重要な計算の不一致、主要操作の故障、意図しない既存機能の破壊、秘密情報の混入は、解消するまで完成・公開扱いにしません。確認できずリスクが大きい場合はpushを保留し、理由を報告します。
- 文書のみの変更は、適用範囲・相互矛盾・リンク・差分を確認します。アプリ実動作テストを実施していない旨を報告します。
- Git操作・公開の許可と完了報告は、ルートのAGENTSに従います。実行していない確認を合格として報告しません。
